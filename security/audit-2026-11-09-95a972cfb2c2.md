- `src/content_parser.rs` reviewed with findings:
  - low: the examples drove the parser with `?` on `parse_end`, which drops the parser on a fatal error before `finish` returns the handles of uploads already stored, and nothing said to finish when the input stops early, so an application following them could leave stored uploads behind on every refused request (also readme.md and context/getting-started.md); fixed in #7.
  - low: under `ParameterRules::Mime`, `name*` and `filename*` take the place of `name` and `filename`, so a reader that ignores extended parameters sees another field name or filename for the same part; accepted, the rules are an explicit opt-in for clients known to send RFC 2231 parameters, and the default for `multipart/form-data` refuses every extended parameter (`// SECURITY:` at `ContentParser::with_parameter_rules`).
  - low: an upload whose content was still arriving when parsing failed, or that ended without the caller giving its handle, has no handle in `Rejected`, so storage the caller began could be left behind (also src/form.rs); rejected, the caller began that storage at `ContentEvent::Upload` and still holds it, since it never gave the parser a handle for it, and the documentation and guide tell it to remove what it stored of an upload still arriving (`// SECURITY:` at `ContentParser::finish`).

- `src/field_value.rs` reviewed with findings:
  - low: text fields can hold NUL, CR, LF, and Unicode controls such as bidirectional overrides, sent raw in multipart content or escaped in URL-encoded content, which could inject into another syntax such as a header, a log line, or a path; rejected, they are data the parser does not interpret, and encoding or checking them for another syntax belongs to the application that writes them (`// SECURITY:` at `impl FieldValue for String`).
- `src/form.rs` reviewed with findings:
  - high: `accepts` builds each upload's `MediaRangeSet` with `MediaRange::from_static`, which panics on a range that is not lowercase tokens, so such a declared range would let any upload for the field panic the parser; rejected, the derive in macros/src/attributes.rs reads each range with `MediaRange::parse` from `base-web-media-type` 0.1, which Cargo resolves to one version for both crates, and declares only its lowercase essence without parameters, which `from_static` accepts, and declarations are trusted application code (`// SECURITY:` at `accepts`).
